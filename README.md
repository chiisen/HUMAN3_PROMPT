# HUMAN 3.01 自我反思訪談提示詞

本專案提供一組以 HUMAN 3.01 四象限框架為靈感的引導式自我反思提示詞。使用者可透過 AI 對話整理心智、身體、靈性與職業等生活領域的經驗，並獲得暫定觀察與反思問題。

這不是經驗驗證的心理測驗、研究量表、醫療工具或心理診斷。AI 產生的層級、階段、元類型、象限關聯與行動建議，都是依有限對話形成的暫定解讀，可能錯誤或不完整，不應視為客觀測量結果，也不能取代心理、醫療、法律、財務或其他專業評估與建議。

## 適用對象與限制

- 適合想透過結構化提問整理自身經驗、檢視生活模式或產生後續反思方向的成年人。
- 教練、教育工作者或助人專業者，可將其作為對話與反思的輔助材料；不得把 AI 結果當成對他人的診斷、經驗驗證的測量或專業判斷依據。
- HUMAN 3.01 分級不能判定高風險行為是否適合個人，也不能判定其安全性；本框架及 AI 無法評估迷幻藥、PEDs／合成代謝類固醇、刻意製造財務困境或其他高風險行為是否適合你。不要用發展分級作為採取風險的許可；相關健康或物質問題請諮詢合格醫療專業人員，重大財務、工作或法律決策請尋求具相關資格且獨立的專業意見。
- 若對話令你感到不適，請停止使用；若正面臨急迫的身心安全問題，請聯絡當地緊急服務或合格專業人員。

## 隱私與使用前提醒

- 避免輸入姓名、地址、電話、電子郵件、工作單位、帳號、精確日期等可識別身分的資料。
- 也避免貼入病歷、檢驗報告、財務帳戶、法律文件、第三人的私密資訊或其他不願交由 AI 服務處理的敏感內容；需要討論時，先移除身分線索並只提供必要概況。
- 對話會如何儲存、用於訓練或分享，取決於你使用的 AI 服務及帳戶設定。開始前請查看該服務的隱私與資料保留政策；本專案不會替該服務保證保密或刪除資料。
- 只回答自己願意分享的內容。可要求跳過任何問題或停止訪談，不必解釋原因。

## 使用方法

1. 選擇你信任且已了解其隱私設定的 AI 服務。
2. 複製 [英文提示詞](./PROMPT.md) 或 [繁體中文提示詞](./PROMPT_TW.md)，貼入對話並依序回答問題。
3. 不確定或不願回答時，輸入「跳過」；要暫停或結束時，輸入「停止訪談」。回答只提供自己願意分享的資訊。
4. 面談後 AI 會先提供短摘要。請先修正不準確處、補充背景或要求補問；只有在確認或明確要求繼續後，才會產生完整報告。你也可以只要求特定章節，或停留在摘要。已確認並選定輸出範圍時，AI 應直接產出，不重複確認。每象限以 3 題為目標、最多 8 題，追問與跳過均計入；停止與拒答優先，不必為湊題數繼續。
5. 即使選擇完整報告，預設行動仍聚焦一項優先問題、一個可逆實驗與回顧條件；額外任務與長期規劃只在你要求且有依據時展開。不計算隱藏分數或百分比：舊公式沒有明定決策用途，且無法處理未判定象限，因此移除。
6. 將結果當作待檢視的反思假設。若證據不足，要求 AI 說明未知之處；不要因為某個標籤或建議而做出重大健康、財務、法律或人生決定。

## 提示詞維護

- `PROMPT.md` 為主要維護來源；修改後再將相同意義同步至 `PROMPT_TW.md`。
- 兩份提示詞以 `prompt-parity` 區段標記對應的重要內容，不要求翻譯逐字一致；新增或重組重要區段時，請在兩份文件保留相同的標記 ID：`model-fundamentals`、`high-risk-safety`、`interview-flow`、`report-format`。
- 使用 Python 標準函式庫執行 `python scripts/check_prompt_parity.py`，檢查必要區段是否在兩種語言中成對存在、標記唯一、內容非空，並比對兩語區段順序及巢狀關係，無需安裝額外套件。此檢查不判斷翻譯品質或語意是否完全等價，仍需人工校閱；請使用 [重要規則雙語對照](docs/PROMPT_RULES.md) 逐項檢查。

## 驗證方式

在專案根目錄執行 `python -B -m unittest discover -s tests -v` 與 `python -B scripts/check_prompt_parity.py`。Python 版本以 `.python-version` 為準；Git 設定測試需要 Git 與 PowerShell 7，且只操作臨時倉庫。

這些測試包含靜態規則文字檢查與工具行為測試，不能證明模型遵循提示詞。請另依 [對話行為驗收案例](docs/CONVERSATION_ACCEPTANCE.md) 在新對話逐輪執行，使用 [結果模板](docs/ACCEPTANCE_RESULT_TEMPLATE.md) 記錄模型、設定、提示詞 SHA、原始輸出及判定理由。雙語、不同模型與不同版本分開記錄；未執行或未覆蓋的情境不能標為通過。本次建立案例時尚未執行外部模型驗收。

Python 快取由 `.gitignore` 忽略，不需刪除既有檔案。

## Git 推送遠端設定

在本專案 Git checkout 或其子目錄內，用腳本實際路徑執行 `pwsh -File ./setup_git_sync.ps1`（根目錄範例），可設定預期的五個 `origin` 推送目的地。任何寫入前會檢查所有 `origin` fetch URL；缺少 origin、主機／擁有者／專案名稱不符時直接拒絕，保留原設定。

支援以下格式，專案名稱限 `HUMAN3_PROMPT`，`.git` 可省略：

- HTTPS：`https://github.com/<owner>/HUMAN3_PROMPT.git`，owner 限 `chiisen`、`edwin45168899`、`edwiin1688`、`NathanEvans1221`；GitLab 限 `https://gitlab.com/chiisen/HUMAN3_PROMPT.git`。
- SSH：`git@<host>:<owner>/HUMAN3_PROMPT.git` 或 `ssh://git@<host>/<owner>/HUMAN3_PROMPT.git`。正式主機使用上述 owner；既有 SSH 別名僅接受 `github.com-chiisen/chiisen`、`github.com-edwiin1688/edwiin1688`、`github.com-NathanEvans1221/NathanEvans1221`、`gitlab.com-chiisen/chiisen` 的配對（此處以斜線表示主機／擁有者，SCP 格式實際使用冒號）。
- 不接受本機路徑、自訂埠、其他主機或 owner、附帶查詢參數的 URL；新增目的地需先更新腳本與測試，不能用同名目錄代替來源檢查。

這是本機 URL 白名單防誤操作，不能證明遠端擁有權或排除 Git／SSH 的額外 URL 重寫設定。腳本只替換本機 `remote.origin.pushurl`，不修改 fetch URL、其他 remote 或全域設定；可重複執行，不會連線遠端或推送。本次只測試臨時倉庫，未對目前 checkout 執行設定腳本。
